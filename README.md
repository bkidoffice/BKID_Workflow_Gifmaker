# BKID Workflowboost GIF Maker 1.8.0

Windows Rhino에서 부품별 Datum CSYS 이동·회전을 순서대로 설정하고 GIF로 저장하는 도구입니다. 원본은 시작 자세에 유지하고 임시 복사본으로 애니메이션을 만듭니다. `.3dm` 파트는 Rhino 문서로 가져오거나 블록으로 삽입한 뒤 선택하세요.

## 설치

1. Rhino를 모두 종료합니다.
2. `installers/BKID_GifMaker_Setup_1.8.0.exe`를 실행합니다.
3. 설치 버튼을 누르고 Rhino Installer에서 **현재 사용자** 설치를 선택합니다.
4. Rhino를 실행합니다. 최초 실행 시 GIF Maker 아이콘이 있는 `BKID Workflowboost` 툴바가 표시됩니다. 이후 도킹·표시 상태는 Rhino 설정을 따릅니다.
5. 툴바를 다시 열려면 `BKIDGifMaker`, 직접 실행하려면 `BKIDGifMakerCapture` 명령을 입력합니다.

EXE는 기존 AutoCrop과 같은 설치 창·재설치 확인·RHI 실행·결과 파일 검증 방식을 사용합니다. 재설치에서 **아니오**를 선택하면 기존 파일을 유지합니다. **예**를 선택하면 GIF Maker의 기존 관리 파일을 삭제한 후 설치하며, 취소·실패 시 이전 버전을 자동 복원하지 않습니다. AutoCrop은 별도 플러그인 GUID로 유지됩니다. 설치 EXE에는 코드 서명이 없습니다.

대체 설치: `installers/BKID_GifMaker_1.8.0.rhi`를 더블클릭하여 Rhino Installer로 설치할 수 있습니다. 이 경로는 EXE의 사전 확인·정리 절차를 거치지 않습니다.

## 사용

1. 모든 파트의 이동 전후가 보이도록 모델 뷰포트를 잡습니다.
2. 첫 파트를 선택하고 Enter로 선택을 확정합니다. 한 단계에 여러 객체를 직접 선택할 수도 있습니다.
3. Datum CSYS 원점을 지정합니다. 축 방향은 Enter=World, `CPlane`=현재 작업 평면, `Custom`=+X/+Y 방향 점입니다.
4. **Datum 기능에서 `Move`(이동) / `Rotate`(회전)**를 선택합니다. Enter 기본값은 Move입니다. 이동은 X·Y·Z 화살표를 사용합니다. 회전은 X·Y·Z 회전 링을 드래그하거나 **상단 명령창의 Angle 옵션**에서 축과 각도(도)를 입력합니다. Enter로 동작을 확정한 뒤 해당 파트의 동작 시간(0.2–10초)을 입력합니다.
5. 첫 파트는 완료 자세로 표시되고 **다음 파트 선택**이 이어집니다. 다른 파트를 선택해 Enter를 누르고 Datum 동작·시간을 설정합니다. 필요한 만큼 반복합니다.
6. 더 추가하지 않으려면 다음 파트 선택에서 **아무것도 선택하지 않고 Enter**를 누릅니다. Esc는 전체 작업을 취소하고 원본을 복원합니다.
7. FPS(5–30)와 GIF 너비를 입력합니다. 너비의 기본값은 현재 뷰포트 1배율이고 종횡비를 유지합니다.
8. 가로 타임라인으로 전체 순차 이동을 확인합니다. 앞 파트는 끝 위치에 남고 그다음 파트가 움직입니다. 회전 단계는 **미리보기 상단 각도 입력란**에서도 값을 바꿀 수 있습니다. 변경하면 완료 자세를 보여주고 저장 GIF에도 같은 각도를 적용합니다. 재생·일시정지·처음·끝 버튼과 PNG 원본 보관 옵션을 사용할 수 있습니다.
9. **GIF 저장…**으로 저장합니다. Rhino 하단에서 PNG 캡처 → GIF 변환 → 저장 진행 상황을 확인합니다.

이미 이동을 설정한 임시 파트는 다음 파트 선택에서 제외됩니다. 같은 파트를 다시 이동시키는 별도 단계는 현재 지원하지 않습니다. 그룹을 자동으로 통째 선택하지 않으므로 함께 움직일 객체는 직접 여러 개 선택하세요.

이동 단계는 시작 위치→끝 위치로 직선 이동하고, 회전 단계는 Datum 원점을 중심으로 실제 호를 따라 회전합니다. 여러 파트의 이동·회전 단계는 선택한 순서로 재생합니다. 이동 드래그 여러 번은 최종 이동량으로 합산하고, 회전 드래그 여러 번은 축·방향·각도와 순서를 기록해 재생합니다. 첫 시작·마지막 끝 위치는 각각 0.5초 유지합니다. 단계별 시간과 전체 시간은 유지하며 각 단계의 경계 프레임도 캡처합니다.

투명 배경과 PNG 프레임 기반 합성을 유지합니다. GIF는 최대 255색/1비트 알파 제약이 있습니다. 원본 PNG 보관을 선택하면 무손실 프레임을 함께 남깁니다. 처리에 필요한 임시 디스크 공간·생성 시간은 파트 수, 전체 이동 시간 및 해상도에 따라 증가합니다. 종료·취소·실패 시 임시 파트를 제거하고 원본 위치·선택 상태를 복원하며 기존 GIF는 새 파일 완성 후 교체합니다.

## 개발 및 검증

대상: Windows 10/11 x64의 Rhino 6 및 Rhino 8의 내장 IronPython 2.7 (`RunPythonScript`). Rhino 8 CPython 3 실행 경로는 지원·검증하지 않았습니다. 사용자 PC에 Pillow·FFmpeg를 별도 설치할 필요가 없습니다. 검증된 Windows FFmpeg LGPL 공유 배포본을 설치 패키지에 포함합니다.

빌드: .NET SDK 8 및 Python 3을 설치하고 저장소 루트에서 실행합니다. 첫 빌드는 고정된 FFmpeg Windows 배포본을 다운로드하고 SHA256을 검사합니다. Python 통합 테스트를 실행하는 개발 PC에는 FFmpeg 7 이상이 PATH에 필요합니다. 설치 프로그램을 쓰는 Windows 사용자에게는 변환기가 동봉됩니다.

```sh
python tools/build_rhi.py --dotnet /path/to/dotnet
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

빌더는 잠금 파일로 의존성을 복원하고 실제 RHP·Windows EXE를 컴파일합니다. Rhino 6.0.18016.23451 SDK로 동적 캡처 API를 별도 컴파일하고, RHP 식별자·내장 Python/GIF 인코더·아이콘·EXE 내 RHI·설치 이미지를 검증합니다. 설치 코드 공유 테스트도 실행합니다.

현재 Linux 검증 결과: Python 테스트 32개 통과(GIF 픽셀·프레임·반복·시간, 모의 Rhino 양방향 미리보기 이동·저장 시 처음부터 재시작·미리보기/저장 취소·미리보기 오류·이동 실패 후 원본·파일 복원), C# 빌드 및 초기 Rhino 6 API 컴파일 통과, 설치 관리·재설치 동의·설치 결과 검증 테스트 통과. 모의 Rhino 테스트는 실제 Rhino 렌더링 테스트가 아닙니다.

**Windows Rhino 6/8 실기기에서 EXE 설치·툴바·IronPython 실행·실제 GIF 캡처는 아직 실행하지 않았습니다.** 두 버전 모두 아래 항목을 확인해야 합니다.

- 설치 후 최초 툴바 표시, 도킹·숨김 후 재시작, `BKIDGifMaker`로 다시 열기
- 단일 부품·다중 부품·블록의 시작/중간/끝 프레임, 원본 위치·선택 복원
- Esc, 저장 취소, 쓰기 불가 폴더, 기존 GIF 덮어쓰기, Undo/Redo
- 한글·공백 경로, 프레임 밖 이동, 큰 모델의 처리 시간
- AutoCrop과 동시 설치, 재설치 취소/승인, Rhino Installer 실행 결과

## 1.0.1 아이콘 수정

AutoCrop 원본 SVG 프레임 좌표·두께·여백과 `#0645F5` 색상을 그대로 사용합니다. `python tools/build_icons.py`는 아이콘을 생성하고 16·24·32·64px에서 모든 프레임 픽셀을 원본과 비교합니다. 기존 GIF Maker 툴바는 최초 업데이트 시 그림을 다시 읽으며 도킹·표시 상태를 보존합니다. 추가 아이콘이 있는 사용자 편집 비트맵 스트립은 자동 교체하지 않고 명령창에 안내합니다. 실제 Rhino에서의 캐시 갱신은 미검증입니다.

## 1.1.0 미리보기와 가로 타임라인

저장 전 저해상도 뷰포트 미리보기를 제공합니다. 가로 슬라이더는 시작~끝의 프레임 위치를 양방향으로 탐색하고 시간·진행률·프레임을 표시합니다. 재생은 실제 경과 시간을 기준으로 갱신하며 슬라이더를 직접 조작하면 일시정지합니다. 미리보기 창은 GIF의 이동 구간을 확인하며 GIF 출력에만 포함되는 양 끝 0.5초 정지는 재현하지 않습니다. 취소·닫기·렌더 오류 때 타이머와 이미지 리소스를 해제하고 임시 부품을 제거합니다. 미리보기 API는 초기 Rhino 6 SDK로 컴파일 확인했으며 실제 Eto 이벤트·렌더링·UI 반응성은 Windows Rhino 6/8에서 검증해야 합니다.

## 1.2.0 투명 GIF와 툴버튼 크기 재확인

미리보기와 최종 캡처 모두 Rhino의 투명 배경을 요청하고 32-bit ARGB를 읽습니다. 투명 인덱스를 따로 예약하고 각 프레임을 지운 뒤 다음 프레임을 표시해 이전 부품 위치가 잔상으로 남지 않게 했습니다. 흰색·검은색 보존, 알파 경계값, 이동 후 투명 영역 복원을 Pillow로 디코딩해 검증했습니다. 실제 Rhino 알파 렌더링은 Windows 호스트에서 확인해야 합니다.

최신 AutoCrop 커밋 `781b0a28c9d697e4c83cd8552d2488106445daed`의 RUI와 비교해 작은/기본/큰 아이콘 크기(16/24/32px), DPI 100, 버튼 표시 방식, 툴바 기본 컨테이너 크기가 동일함을 확인했습니다. 이미 설치된 GIF Maker 툴바도 최초 업데이트 시 같은 비트맵 크기·표시 방식으로 새로 읽습니다. 도킹·사용자 창 위치는 유지하며 Rhino 전체의 UI 배율을 강제로 바꾸지 않습니다. 실제 화면의 크기는 Rhino 아이콘 크기 설정과 Windows 배율에도 영향을 받습니다.

## 1.2.1 기본 화질: AutoCrop 1배율 해상도

기존 고정 800px 기본 너비와 1600px 제한을 없애고 현재 `ActiveViewport.Size.Width/Height`를 기본 캡처 크기로 사용합니다. AutoCrop `capture_scale=1.0`의 크롭 전 캡처와 같은 픽셀 기준이며 확대 보간으로 크기만 늘리지 않고 Rhino ViewCapture에 해당 해상도를 직접 요청합니다. 미리보기 창은 반응성을 위해 축소 렌더링하고 최종 GIF는 지정한 해상도로 다시 캡처합니다. 투명 배경은 유지합니다. GIF의 255개 불투명 색상·1비트 투명도 제한으로 AutoCrop PNG와 색상·반투명 표현이 완전히 같지는 않습니다. 1920×1080 모의 뷰포트의 기본 출력 크기를 실제 GIF 디코딩으로 확인했습니다.

## 1.3.0 PNG 캡처를 모아 GIF 생성 / 저장 진행 상황

각 위치를 AutoCrop과 같은 ViewCapture 설정으로 투명한 원본 PNG에 먼저 저장합니다. 모든 PNG가 만들어진 다음 해당 파일들을 다시 읽어 GIF로 합치며, 변환 단계에서는 Rhino를 다시 렌더링하거나 재질·조명·표시 모드를 바꾸지 않습니다. 기존 고정 RGB 3:3:2 색상 변환 대신 각 PNG의 색으로 적응형 팔레트를 생성합니다. 투명 영역 외의 색이 255개 이하면 원본 RGB를 그대로 보존하고, 더 많으면 가중 중앙값 분할과 오차 확산으로 그라데이션·표면 표현 손실을 줄입니다. GIF 자체의 255색/1비트 알파 제한 때문에 모든 캡처를 PNG와 픽셀 단위로 같게 만들 수는 없습니다.

원본 PNG 보관 옵션을 선택하면 GIF 옆의 `파일명_PNG` 폴더에 무손실 프레임을 남깁니다. 같은 이름의 폴더가 있으면 고유한 접미사를 붙여 기존 폴더를 보존합니다. 옵션을 선택하지 않으면 변환 후 임시 PNG를 정리합니다. 캡처용 임시 디스크 공간이 필요합니다.

진행률은 PNG 캡처·이미지 변환·GIF 기록의 처리 단계 기준이며 예상 남은 시간을 뜻하지 않습니다. 성공·실패·취소 때 이 작업이 생성한 진행률 표시만 해제합니다. 기존 GIF는 새 GIF가 완성된 후에만 교체합니다.

검증: Python 통합·GIF 디코딩 테스트 14개 통과. 모든 PNG를 먼저 만든 뒤 합치는 순서, PNG의 표면 RGB와 투명도, 변환 실패 후 기존 파일·원본·진행률 복원, PNG 보관을 확인했습니다. 실제 배포용 C# 색상 변환 코드 테스트는 255색의 원본 RGB 보존·투명도·표면 색상 오차 감소를 확인합니다. 테스트 그라데이션의 평균 제곱 오차는 기존 고정 팔레트 324.42에서 11.44로 줄었습니다. 이 수치는 테스트 이미지 결과이며 모든 실제 모델의 화질을 보장하지 않습니다. Windows Rhino에서의 실제 재질·뷰포트 렌더링과 진행률 UI는 여전히 실기기 검증이 필요합니다.

## 1.4.0 저장된 GIF의 면 표현 수정

사용자가 미리보기·캡처가 아니라 저장된 GIF에서만 면이 깨진다고 확인했으므로, 정상 PNG 캡처 경로와 모델 이동은 유지했습니다. 1.3.0의 자체 적응형 색상 변환·오차 확산·GIF 인코더는 배포 실행 경로에서 제거했습니다. 캡처 PNG들을 표준 FFmpeg로 합치고 **디더링을 끄며**, 모든 프레임이 **같은 색상표**를 사용하게 했습니다. 표면에 인위적인 점무늬가 생기거나 프레임마다 색상표가 달라지는 문제를 줄입니다. 재질·조명·면·메쉬에는 추가 변환을 하지 않습니다. GIF 자체의 색상 수 제한은 남습니다.

실제 FFmpeg를 실행한 테스트에서 PNG의 회색·흰색·검은색 RGB, 프레임 수·지연 시간, 투명 배경, 이전 위치의 잔상 제거를 확인했습니다. 255색을 넘는 그라데이션 면을 여러 위치로 이동한 테스트도 같은 표면 픽셀의 표현이 위치마다 달라지지 않는 것을 확인했습니다. C# 프로세스 코드의 한글·공백·따옴표 경로, 진행 출력·오류 수집 및 취소를 실제 자식 프로세스로 검증했습니다. Windows 변환기 파일은 공식 체크섬으로 검증했고 설치 확인도 변환기 파일의 크기·해시를 요구합니다. Windows Rhino에서의 실제 사용자 모델은 아직 재현 실행하지 못했습니다.

다운로드 ZIP은 설치 EXE와 설명서를 포함합니다. 중복된 대용량 RHI는 ZIP에서 제외했으며 별도 RHI도 `installers`에 제공됩니다. 변환기 동봉으로 설치 파일은 약 80MB입니다. FFmpeg 버전·소스·라이선스·해시는 [third_party/ffmpeg/NOTICE.md](third_party/ffmpeg/NOTICE.md)에 기록했습니다.

## 1.5.0 Datum CSYS 축 드래그 이동

기존 시작점/끝점 지정 대신 파트 선택 → Datum 원점/축 설정 → 축 화살표 드래그 → Enter 확정 순서로 이동을 정의합니다. 화살표는 설정한 Datum의 로컬 X/Y/Z 방향을 사용하고, 여러 드래그의 합을 최종 이동량으로 저장합니다. 미리보기에는 Datum 기준 ΔX/ΔY/ΔZ와 문서 단위를 표시합니다. 애니메이션은 기존과 같이 시작 위치에서 최종 위치까지 직선 이동하며, 드래그 각각을 별도 경로 구간으로 녹화하지 않습니다.

Gumball 조작은 Rhino의 TransformObjectList 표시 피드백을 사용하며 원본 파트에 실제 변환을 커밋하지 않습니다. 확정/취소/예외 시 조작용 표시를 해제한 뒤 기존 미리보기·PNG 프레임 캡처를 진행하므로 Datum 화살표가 GIF에 포함되지 않습니다. 모델의 CPlane이나 Rhino 전체 Gumball 설정도 변경하지 않습니다. Datum은 이번 실행의 이동 기준이며 문서에 영구 Datum 객체를 추가하지 않습니다.

검증: 초기 Rhino 6 SDK로 실제 Gumball/좌표계 설정 코드를 컴파일했습니다. 회전된 Datum 축의 로컬/월드 변환·음수 이동·기울어진 Z축·비정상 수치 거부를 배포 소스 파일로 실행 검증하고, Datum 단계 취소 시 모델·출력·진행 표시가 그대로인 것을 통합 테스트했습니다. 마우스 축 선택·드래그 및 Rhino 6/8 실기기 UI 동작은 이 Linux 환경에서 실행하지 못했습니다.

## 1.6.0 여러 파트의 순차 이동 추가

첫 파트의 Datum 이동과 시간을 정한 뒤 다음 파트를 이어 선택할 수 있습니다. 먼저 설정한 파트의 임시 복사본은 끝 위치에 유지하고 다음 파트만 Datum으로 조작합니다. 이동을 이미 지정한 파트의 임시 복사본은 다시 선택할 수 없습니다. 다음 파트 선택에서 빈 상태로 Enter=설정 완료, Esc=전체 취소입니다.

전체 타임라인은 단계별 시간을 합산해 재생합니다. 이전 파트는 완료 위치, 아직 시작하지 않은 파트는 원래 위치에 유지됩니다. 뒤로 탐색할 때도 모든 파트의 상태를 해당 시점으로 복구합니다. 각 단계 경계를 프레임 목록에 포함해 파트 이동이 끝나는 순간이 누락되지 않도록 했습니다.

검증: Python 테스트 32개 통과. 실제 FFmpeg로 두 파트의 시작/첫 파트 완료/두 번째 파트 완료 프레임을 저장하고, 뒤로 탐색·두 번째 파트 선택 취소·두 번째 Datum 취소·원본 및 진행 표시 복원을 확인했습니다. 다음 파트 선택 및 제외 필터를 포함한 실제 C# 코드를 초기 Rhino 6 SDK로 컴파일했습니다. Windows Rhino 6/8에서 연속 선택과 마우스 조작은 실기기 검증이 필요합니다.

## 1.7.0 Datum 이동/회전 선택

Datum 원점과 축을 정한 뒤 `Move`/`Rotate`를 고릅니다. Move는 이동 화살표만, Rotate는 회전 링만 표시하고 스케일·자유 이동은 비활성화합니다. 회전 중심은 선택한 Datum 원점입니다. 회전 링은 파트와 함께 회전하는 현재 Datum의 로컬 X/Y/Z 방향을 따릅니다.

여러 회전 드래그는 실제 드래그 순서와 방향을 기록하고, 각 드래그의 절대 각도에 비례해 해당 단계 시간을 배분합니다. 180도 경계를 넘어도 방향을 유지하며 360도·720도를 최종 자세가 같다는 이유로 0도로 취급하지 않습니다. 미리보기와 PNG 프레임 캡처 모두 같은 회전 경로를 사용합니다. 타임라인을 되돌릴 때 이전 자세의 역변환과 목표 자세를 적용해 회전 중심·순서를 유지합니다. 매우 짧은 동작 시간과 낮은 FPS는 회전 중간 프레임을 충분히 보여주지 못할 수 있으므로 기본 2초·15FPS 이상을 권장합니다.

검증: Python 테스트 32개 통과. Datum이 물체 중심에서 떨어져 있을 때의 회전 호, 양/음 방향, 360도, 다축 회전 순서, 앞뒤 탐색, 이동→다른 파트 회전의 순차 상태·복원과 실제 GIF 생성 경로를 확인했습니다. 배포용 C# 각도 추적 소스로 ±720도 경계 통과를 실행 검증했고 회전 링·회전 변환 API는 초기 Rhino 6 SDK로 컴파일했습니다. 실제 Windows Rhino 6/8의 마우스 회전 링 조작은 미검증입니다.

## 1.8.0 상단 회전 각도 입력

Rotate 모드에서 Rhino 상단 명령창의 `Angle`을 선택하면 축(X/Y/Z)과 각도(도)를 입력할 수 있습니다. 아직 링을 드래그하지 않고 Enter를 눌러도 이 입력으로 들어갑니다. 기본은 Z축 90도이며, 기존 드래그가 있으면 마지막 회전의 축·각도를 수정합니다. 같은 각도를 추가로 더하는 방식이 아닙니다. 설정 후 Enter로 회전을 확정합니다.

미리보기 창 상단에는 파트·회전축별 각도 입력란을 추가했습니다. 소수점 3자리, -36000~36000도 범위이며 음수는 반대 방향, 0은 해당 회전 없음입니다. 값을 바꾸면 재생을 멈추고 완료 자세로 이동해 결과를 보여줍니다. 다시 재생하거나 타임라인을 움직여 변경한 회전 경로를 확인할 수 있습니다. 필드가 많으면 각도 영역 안에서 스크롤할 수 있고, 최종 GIF의 해상도는 줄이지 않습니다.

이전 회전의 각도를 바꾸면 뒤따르는 회전의 로컬 축도 다시 계산합니다. 기존 자세를 먼저 제거한 뒤 새 자세를 적용해 각도를 누적해서 잘못 더하지 않습니다. 0도 단계는 동작 시간을 유지한 채 정지 상태로 재생합니다.

검증: Python 테스트 32개 통과. 180→90도 수정이 실제 PNG/GIF 생성 경로에 반영되는지, 음수·0·360도, 완료 자세에서의 재입력, 앞선 각도 변경 후 후속 로컬 축 재계산을 확인했습니다. NumericStepper·상단 명령창 GetNumber API는 초기 Rhino 6 SDK로 컴파일 검증했습니다. 실제 Windows Rhino의 입력 포커스·마우스·Eto UI 동작은 미검증입니다.
